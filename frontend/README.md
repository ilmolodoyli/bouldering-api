# Турнир: судейский фронт (разработка)

Согласованный тёмный стеклянный интерфейс, быстрые действия и отдельное исправление.
Это не готовый к турниру продукт: текущий сервер не содержит авторизации или чтения результатов.

## Запуск

Нужны Python 3.10+ и современный браузер. Без npm-зависимостей.

```sh
cd frontend
python3 serve.py
```

Откройте http://127.0.0.1:8781 . Не открывайте index.html через file://: используются JS-модули.
`BOULDER_API=https://your-backend.example python3 serve.py` задаёт сервер. По умолчанию используется предоставленный ngrok-адрес, который может измениться.

- **Тренировка**: вымышленные участники, реальные локальные действия и история. Не пишет в API. Перезагрузка не сбрасывает счёт; можно выгрузить JSON через Профиль. Это не аккаунт, не синхронизация и не резервная копия.
- **Живой API**: чтение участников и трасс через локальный same-origin proxy. Сервер записи блокирует. Нет выдуманного входа или клиентской выдачи ролей.
- Быстрые действия закрывают карточку сразу после успешного локального сохранения. При ошибке localStorage действие не применяется.
- Панели открываются за 160 мс и закрываются за 120 мс. Сохранение применяется сразу, уходящая панель не принимает ввод. Кнопки дают короткий отклик. При prefers-reduced-motion движение и переходы выключены.
- Каждое действие добавляет ровно одну попытку. Первая зона сохраняется; топ завершает трассу. Исправление работает отдельно.
- Топ без ранее взятой зоны разрешён: добавляет одну попытку и ставит зону и топ на эту же попытку. Если зона уже есть, её первая попытка сохраняется. Один готовый пакет содержит оба значения; живые записи остаются заблокированы до безопасного контракта API.

## Контракт API, проверено 28.10.2026

Исходный backend: commit 94900366afacdc45494df0b6d56ba90282baacbd.
OpenAPI: https://agile-sandbag-viewless.ngrok-free.dev/openapi.json

`GET /competitors/?skip=0&limit=100`, `GET /routes/?skip=0&limit=100`.
`POST /results/` принимает абсолютные значения:

```json
{"competitor_id":1,"route_id":3,"total_attempt":4,"zone_attempt":2,"top_attempt":4}
```

Именно `total_attempt`, не `total_attempts`. Невзятая зона/топ = 0, не null.
Код backend делает upsert по competitor_id+route_id, тем же POST можно исправлять запись. Адаптер `Api.save` реализован и проверяет точное совпадение ответа, но не вызывается живым UI до безопасного серверного контракта.

Не хватает:
1. Авторизации/регистрации, серверной роли и проверки Judge/Admin при записи.
2. Чтения результата участника на трассе и списка результатов. Без baseline нельзя безопасно начать с нуля после нового устройства/вкладки или неизвестного ответа сети.
3. Версии результата/защиты от конкурентной перезаписи, уникальности пары, идемпотентности. Нельзя автоматически повторять абсолютный старый payload поверх нового счёта.
4. Сессионного выбора трасс и серверного протокола/ранжирования.
Правило зоны согласовано: топ автоматически ставит отсутствующую зону на ту же попытку, первая ранее взятая зона не меняется.

CORS отсутствует в текущем backend; локальный прокси решает чтение для разработки, но не является авторизацией и не делает production безопасным. Не включать публичный прокси на localhost. Записи запрещены явно.

## Проверки

```sh
npm test
```

Node 18+. Проверки правил, валидатора и точного POST-контракта. UI дополнительно проверен настоящим браузером: падение, зона, повторная зона, топ, исправление, перезагрузка, изоляция трасс, навигация и ширины 320/390/1024.
Неизменённый backend отдельно проверен в изолированной SQLite БД: upsert/исправление сохраняют одну строку с тем же id. В живую БД тестовые записи не отправлялись. Это не доказывает работу PostgreSQL, авторизации или production-параллельности.

Backend и main не изменены. Приложение не хранит и не запрашивает пароли или токены.
